# Capture settings and Mac distribution

## What Veyra exposes

Veyra 2.2.0 targets Windows 11 and DirectX 12. Its Professional view separates picture enhancement, frame generation, colour, sound and display. The README suggests verifying the plain input first and then enabling one effect at a time. Its low-queue, display-sync and output-cap controls are separate from the frame-generation multiplier. [Veyra README](https://github.com/Likely7/Veyra-NRVideo/blob/v2.2.0/README.md) · [Presentation controls](https://github.com/Likely7/Veyra-NRVideo/blob/v2.2.0/qml/Veyra/ProPresentationRows.qml)

## What Meyra measured

The Mac app in the Reddit post is **Meyra**. Its author estimated 30–50 ms of added delay on one Xbox Series S setup. The repository identifies the tested card as a Blackmagic UltraStudio Recorder 3G and describes USB cards as untested. Its November 22 README reports **22.6 ms** with Apple's 720p interpolator and **30.6 ms** at full size using its early schedule and percentile-based deadline. Both numbers run from a real frame arriving in the app to the call submitting it for presentation. The preset table used recorded footage on an M4 Max in a 2450 × 1378 window at 100 Hz. The renderer logs Metal's later presentation timestamp separately. [Author’s post](https://www.reddit.com/r/macgaming/comments/1y0v2pa/made_an_open_source_mac_app_that_turns_gta_6s_30/) · [Benchmark conditions and settings](https://github.com/k33bs/meyra/blob/9c8923cb7588b22c6633341d19847f4b3e9cf4eb/README.md) · [Renderer timing](https://github.com/k33bs/meyra/blob/9c8923cb7588b22c6633341d19847f4b3e9cf4eb/src/renderer.mm#L1096-L1120)

Three Meyra controls address problems specific to captured video. A tolerant repeat detector compares each input with the last distinct picture so small card-level fluctuations can be ignored while a slow pan accumulates detectable motion. User-marked HUD rectangles reuse real pixels in generated frames. An early deadline can discard a late midpoint to leave the next refresh free for the real frame. On a 60 Hz screen, a missed midpoint in a 30→60 sequence has no spare refresh before that real frame. [Cadence implementation](https://github.com/k33bs/meyra/blob/9c8923cb7588b22c6633341d19847f4b3e9cf4eb/src/cadence.h) · [Motion controls](https://github.com/k33bs/meyra/blob/9c8923cb7588b22c6633341d19847f4b3e9cf4eb/README.md#what-each-thing-does)

## Settings that fit Second Frame

- **Input and motion.** Offer the external card and its advertised AVFoundation modes. Distinguish *capture rate* from *game frame rate* in the UI. For 30 fps gameplay over a 60 Hz capture link, a 2× option can generate one midpoint between distinct pictures. Direct playback serves native 60 fps content. Show the active signal and count confirmed presentations and generated presentations separately. [Apple capture formats and rates](https://developer.apple.com/library/archive/technotes/tn2445/_index.html) · [Apple frame interpolation](https://developer.apple.com/documentation/videotoolbox/vtlowlatencyframeinterpolationconfiguration) · [Metal presentation timestamp](https://developer.apple.com/documentation/metal/mtldrawable/presentedtime)
- **Picture and latency.** Start from the approved SDR colours, 720p temporal guide and full-resolution source detail measured on this M4 Pro. Keep original-size and fit-to-display options available for checking HUD text. Compare queue or deadline changes on moving footage with the same card, refresh rate and effects. Record both callback-to-presentation and capture-timestamp-to-presentation, plus p95 frame interval and missed midpoints. Controller-to-screen comparisons require a physical measurement with a common visible stimulus. [Second Frame measurements](../CONTRIBUTING.md#what-the-latency-number-measures) · [Meyra’s timing implementation](https://github.com/k33bs/meyra/blob/9c8923cb7588b22c6633341d19847f4b3e9cf4eb/src/renderer.mm#L1096-L1120)

## Shipping a DMG

**Public Developer ID release.** Sign the app with a Developer ID Application identity, Hardened Runtime and a secure timestamp. Stage the app in a read-only compressed DMG and sign the image with the same type of identity. Submit the outer DMG using authenticated `notarytool`, wait for acceptance, staple the ticket to the DMG and validate it. Test the downloaded image on a different Mac with Gatekeeper enabled. [Apple distribution signing](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac) · [Apple packaging guide](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution) · [Notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)

**Local build without credentials.** An ad-hoc signature (`codesign --sign -`) supports local development. A DMG can still be created with `hdiutil`, mounted and checked for packaging errors. Label that artifact **ad-hoc signed app, unnotarized DMG**. A successful local signature check or SHA-256 match establishes integrity. Public Gatekeeper distribution requires the Developer ID identity and Apple’s notarization ticket described above. [Second Frame build script](../scripts/build.sh) · [Apple notarization requirements](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)
